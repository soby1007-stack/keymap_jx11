# JX-11 키맵퍼 (Shizuku)

JX-11 블루투스 리모컨의 입력(스크롤 휠/버튼)을 읽어 원하는 동작으로 바꿔 주는 앱.

## 키 매핑 표
| 기능 | 키 매핑 | 추가 | 삭제 |
|---|---|---|---|
| 볼륨 올림 | REL_WHEEL(+), KEY_PAGEUP, 스와이프 ↑ | ＋ | － |

- ＋ : 누른 뒤 JX-11 입력을 하면 그 기능에 등록 (한 기능에 여러 개 가능)
- － : 그 기능에 지정된 입력을 체크박스 목록으로 띄움 → 지울 것만 체크 해제 → [적용]
- 같은 입력은 한 기능에만 지정 (다른 기능에 있던 건 자동으로 옮겨짐)

### 지정 가능한 기능
- 볼륨 올림/내림은 기본이 "키 입력 주입"(Shizuku) → 이북 앱의 볼륨키 페이지 넘김도 동작. 끄면 AudioManager 직접 조절
- 앱 권한만으로: 볼륨 올림/내림, 음소거, 재생/일시정지, 다음 곡, 이전 곡
- 키 주입 동작: 뒤로, 홈, 최근 앱, 방향키 4개, 확인, 알림창 열기, 전원(화면 켜기/끄기)

## JX-11 은 터치패드형
- 휠이 아니라 BTN_TOUCH + 좌표(ABS)로 입력이 옴 → 앱이 좌표 이동을 **스와이프 ↑↓←→ / 탭**으로 변환 (손가락이 떨어질 때 스와이프 1번 = 휠 1칸. 최소 이동량은 설정에서 조절)
- 표에서 ＋ 후 JX-11을 쓸어 넘기면 스와이프 방향이 등록됨 (BTN_TOUCH 자체는 등록 제외)
- 로그의 `RAW` / `GESTURE` 줄(D 레벨)에 실제 이벤트가 찍힘 → 동작 이상하면 로그 복사해서 전달

## 원래 동작 막기 (v0.3.0)
- 설정의 "JX-11 독점" (기본 켜짐): 네이티브(JNI) `EVIOCGRAB`으로 장치를 독점 → 안드로이드가 JX-11 터치/스크롤을 받지 못하고 앱만 받음
- 로그 `GRAB 독점 성공` 이 보이면 적용된 것. 실패하면 이유(errno)가 찍히고 독점 없이 동작
- 앱/서비스가 종료되면 독점은 자동 해제

## 연결 방식 (v0.4.0): Shizuku 또는 무선 ADB
- 앱 안 [연결 방식]에서 **자동**(Shizuku 우선, 안 붙으면 무선 ADB) / Shizuku만 / 무선 ADB만 선택
- 무선 ADB: [무선 ADB 연결(페어링)] → 무선 디버깅 켜기 → '페어링 코드로 기기 페어링' → **알림창**에 6자리 코드 입력 (Kadb 1.2.1)
- 페어링 후 앱이 `app_process`로 shell 권한 서버(`AdbServer`)를 띄움 → 127.0.0.1 소켓+랜덤 토큰으로 통신. 한 번 띄우면 Wi-Fi가 꺼져도 재부팅 전까지 유지
- 서버 로그: `/data/local/tmp/jx11_server.log` · 앱 로그의 `ADB` 단계
- 앱을 업데이트하면 서버 버전이 달라져 자동으로 종료되므로 [무선 ADB 연결]을 한 번 더 누르세요 (이미 페어링했으면 무선 디버깅만 켜 두면 됨)

- BA 앱 방식 반영(v0.5.0): 버튼 한 번에 무선 디버깅 항목으로 이동 + 마법사 시작, 상태 알림에 처음부터 [코드 입력] 표시, 페어링 코드 창이 뜨면 팝업 알림(창이 닫히면 자동 정리), 페어링·연결은 127.0.0.1 + 이 폰에서 실제 열린 포트만 인정, 서버가 이미 떠 있으면 재사용, 버튼을 다시 누르면 처음부터 재시작
- 코드 입력은 알림창(상단바)에서: 6자리 코드만 입력하거나, 포트가 안 잡히면 "37755 123456" 처럼 포트+코드 입력

## 스크롤 방식 (v0.8.0, 배율 입력은 v0.8.1부터 네 자리 스피너 10~9999%)
프리셋마다 휠(세로 이동) 처리 방식을 고른다 (프리셋 탭 → '스크롤 방식').
- **키 변환** (기존): 휠을 N‰ 움직일 때마다 볼륨/방향키/페이지 키 1회. 이북 페이지 넘기기용
- **스와이프**: 휠 이동량 × 배율(10~9999%)만큼 가상 손가락이 화면을 끈다. 100% = 기본 휠 동작과 같은 이동량. 어떤 앱에서든 동작, 손 뗄 때 관성(켜기/끄기)
- **마우스 휠**: 휠 한 칸 = 마우스 휠 1.0 × 배율. 브라우저/웹뷰에 적합, 마우스 휠을 무시하는 앱도 있음
- 셸 프로세스(Shizuku UserService / 무선 ADB 서버)가 `IInputManager.injectInputEvent` 로 직접 주입 (앱 왕복 없음). 가로 이동(◁ ▷ 키), 탭, 타원 키는 그대로 키 지정표를 따른다
- 스와이프는 가상 손가락이 화면 가장자리(위·아래 15%)에 닿으면 취소 후 중앙에서 다시 잡아 이어서 끈다
- 주입이 막혀 있으면 로그 `INJECT` 에 이유가 찍히고 해당 프레임은 키 변환 방식으로 대체된다
- 로그 단계: `SCROLL`(시작/끝/재잡기/배율 전달), `INJECT`(주입 실패 원인), `PRESET`(적용 프리셋의 방식 변경)
- 무선 ADB 서버 프로토콜에 `SCROLL` 명령이 추가돼 서버 버전이 올라감 → 업데이트 후 [무선 ADB 연결]을 한 번 더 누를 것

## 구조
- Shizuku UserService(shell 권한)가 `/dev/input/event*`를 직접 읽어 앱으로 전달, 키 주입 동작도 담당
- 앱(포그라운드 서비스)이 규칙 매칭 → 민감도 엔진 → 동작 실행
- 원래 입력 동작 차단은 장치 독점(EVIOCGRAB)으로 시도

## 사용 순서
1. Shizuku 설치 후 실행(무선 디버깅으로 시작)
2. 앱 열기 → [Shizuku 권한 요청] 허용 → [키맵퍼 켜기]
3. 표에서 기능별 ＋ 로 JX-11 입력 등록
4. 민감도 슬라이더 조절 (스크롤 몇 칸에 1회 동작 / 연속 동작 간격 / 반복 횟수)

## 문제 생기면
- 앱 안 [로그 보기] → [복사] 해서 전달 (단계별: SHIZUKU / BIND / DEVICE / READ / EVENT / MAP / FIRE / ACTION / INJECT / LEARN)
- 앱이 죽으면 오류 화면이나 알림으로 원인 체인이 표시됨
